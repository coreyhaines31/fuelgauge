How to stop hitting your Claude limits

Most limit trouble in Claude Code comes from a few habits. Here's what uses your limit fastest, what saves the most, and how to see a wall coming.

The short answer

Claude Code sends your whole conversation with every request, so long sessions are the biggest drain. Run /clear between unrelated tasks, match the model and effort level to the job, turn off MCP servers you aren't using, and send noisy work to subagents. Then watch your pace, so you know before a big task whether your limit will last.

Why usage climbs in a long session

Claude Code sends the full conversation with every request, and again with each batch of tool results. Caching makes re-reading history cheaper, but it still counts, so a one-line question in a session that's been open all day draws usage for the whole conversation.

Other things that add up while you're not looking:

  • Cache misses: your first message after a long break reprocesses the full context.
  • Scheduled loops: a /loop task fires on its interval even while you're idle, sending your full context each time.
  • Subagents and agent teams: each one sends its own requests. Agent teams can use about 7x the tokens of a normal session when teammates run in plan mode.
  • Compacting a huge context: /compact reads everything it summarizes, so it's a big request itself.

On Pro and Max, /usage flags any of these that accounts for 10% or more of your recent usage.

What saves the most

  1. Clear between tasks. /clear starts fresh when you switch to unrelated work. Use /rename first so you can /resume it later.
  2. Match the model to the job. Sonnet handles most coding tasks and costs less than Opus. Save Opus for hard architecture and multi-step reasoning, and switch with /model.
  3. Lower the effort for routine work. Extended thinking is billed as output. /effort turns it down for simple tasks.
  4. Trim MCP servers. Run /mcp and turn off servers you aren't using. A CLI like gh is often cheaper than an MCP server for the same job.
  5. Move instructions into skills. CLAUDE.md loads into every session. Workflow-specific instructions in skills only load when used. Keep CLAUDE.md under about 200 lines.
  6. Send noisy work to subagents. Test runs, log digging, and doc fetching stay in the subagent's context, and only a summary comes back. Give simple subagents a smaller model.
  7. Be specific, and plan first. "Add input validation to the login function in auth.ts" costs far less than "improve this codebase". Plan mode (Shift+Tab) catches a wrong direction before it's expensive.

See the wall before you hit it

Habits stretch your limit. Knowing your pace tells you when to use them. Fuel Gauge is a free Mac menu bar app that reads your limits from Claude Code after every reply and says, at your recent pace, whether you'll make it to the reset: "Makes it to reset" or "Runs out around 3:40p, 1h 20m early", with the most you can use per hour and still make it. When it says you won't, that's the moment to switch to Sonnet, clear, or save the big job for after the reset.

Agents can check too: fuelgauge status exits with code 2 when a limit will run out before it resets. See Fuel Gauge for agents.

Questions

Why do I hit my Claude limit so fast in Claude Code?

Claude Code sends the whole conversation with every request, so long sessions, subagents, scheduled loops, and cache misses after breaks all add up. /usage shows what used it.

Does switching models help when I hit the limit?

Not for the session or weekly limit, which cover every model. It does help after a model-specific message like "You've hit your Opus limit".

What's the single biggest saver?

Running /clear between unrelated tasks, so each request doesn't carry a long history it doesn't need.
