Don't hit your limit mid-task.

Fuel Gauge watches your Claude Code, Codex, Grok Bot, and Cursor limits and tells you, at your current pace, whether you'll make it to the reset. If you won't, it tells you when you'll run out.

55% used. Is that a problem?

It depends on how fast you're going and how long until the reset. Fuel Gauge does that math for every limit and gives you the answer in plain words: “Makes it to reset” or “Runs out around 11:50a.”

The menu bar pump fills with the fuel left in whichever limit is closest to running out. It turns orange when one won't make it to the reset, and red when one is out.

How the forecast works.

No guesswork about your plan. It reads the same numbers your tools show you, and watches how fast they climb.

1

It reads what's already there

A reading every time Claude Code replies, through its status line. Codex's session logs and Grok Bot's local usage cache fill in the rest.

2

It measures your pace

How much usage climbed over the recent stretch: the last hour for 5-hour limits, the last day for weekly ones.

3

It projects to the reset

If that pace holds, do you hit 100% first? You get a verdict and a range, not a fake-precise minute.

It waits for enough readings before it forecasts: 10 minutes for a 5-hour limit, 3 hours for a weekly one. Until then it says “Learning your pace.” It's an estimate from your recent pace, not a promise.

Let your agent check first.

fuelgauge status exits with code 2 when a limit is forecast to run out before it resets. So an agent can check before a big job, and ask you before it burns through what's left.

  • fuelgauge status --json for the details
  • fuelgauge history for the readings behind it

Questions

Is it accurate?

It's an estimate from your recent pace, not a promise. Speed up or slow down and the forecast moves with you. That's why it shows a range, like “Between 11:31a and 12:14p at your recent pace,” instead of one exact minute, and why it waits for enough readings before it forecasts at all: 10 minutes for a 5-hour limit, 3 hours for a weekly one.

Does it work with Claude Pro and Max?

Yes. It uses the 5-hour and weekly limits Claude Code reports for your plan, so it works on Pro and Max. The status line is where those readings come from, so turn it on.

Which tools does it track?

Claude Code's 5-hour and weekly limits, Codex's weekly limit, Grok Bot's weekly limit, and, if you turn it on, Cursor's monthly limit. Choose which ones to watch in Settings › Tools.

Does it send my data anywhere?

No. It reads only what those tools already save on your Mac. No browser cookies, no Full Disk Access, no keychain, no sign-in, and zero telemetry. The only network request is the check for updates, plus Cursor's usage if you turn Cursor on.

How is it different from CodexBar?

CodexBar covers far more providers, over 100, and leads with percent used. Fuel Gauge covers four tools and leads with the verdict: will you make it to reset. It adds a Claude Code status line and an exit code agents can check, and it reads local files (Cursor, which keeps none, is the one opt-in exception). The full comparison.

How do I remove it?

Run fuelgauge uninstall-statusline first, so your Claude Code status line goes back to how it was. Then run brew uninstall --cask fuelgauge. If you installed from the DMG, drag Fuel Gauge from Applications to the Trash instead.

Is it really free?

Yes, at home or at work. No account, no trial, no subscription. The source is on GitHub under the FSL-1.1-MIT license.

Any Mac with macOS 14 Sonoma or later, Apple Silicon or Intel.
